# Сервер синхронизации — план

Статус: **не развёрнут.** Сервер Анны подходит по ресурсам и правилам (оценка по её инструкции `ANNA-SERVER.md`,
которая хранится у Анны, а не здесь). Фактическое состояние сервера проверяется при развёртывании.

## Требования
- Приложение продолжает работать **без интернета**; сервер — только копия и обмен между устройствами.
- **Сквозное шифрование:** телефон шифрует каждую запись паролем синхронизации до отправки. На сервере — только шифр
  и служебные поля (`coll`, `id`, `updatedAt`), прочитать данные там невозможно.
- **HTTPS обязателен:** приложение открыто по https, браузер не пустит запросы на http. Нужен домен и обратный прокси
  с сертификатом (Caddy).
- Сервис живёт отдельно от остального на сервере, слушает только локальный порт, ограничен по памяти.

## Как будет устроено
- **Сервер:** маленький Node.js без зависимостей, хранение в SQLite/файле, правило «побеждает более позднее».
  API: `POST /sync` { since, changes } → { changes, now }; `GET /health`. Вход — длинный случайный токен устройства.
- **Клиент:** уже есть `changesSince()` и `applyRemote()` (см. ARCHITECTURE). Добавится шифрование, экран
  «Синхронизация» и фоновый обмен при появлении сети.
- **Резервные копии:** данные остаются на каждом устройстве; плюс ежедневная копия базы на сервере.

## Развёртывание
Выполняет Claude Code на Mac Анны (у него есть доступ к серверу), строго по `ANNA-SERVER.md`.
Перед открытием портов наружу — сказать Анне, что станет доступно.

## Решения
- Домен: **свой** (Анна покупает). Для сервиса — поддомен (например, `sync.<домен>`), A-запись на сервер,
  у Cloudflare — режим «DNS only». Имя домена сюда можно записать после покупки, адрес сервера — нет.
